Familiar code. Familiar conventions. Easier movement between teams.

0:45 · Oscar · Opening 2/11

Let's start with the ABC. InnerSource brings open source practices inside an organization. Teams make source code, libraries and documentation discoverable and reusable. [Step 1] Another team can adopt that work and understand the conventions behind it. [Step 2] When they need an improvement, they can propose it through a reviewed pull request. That contribution path is what turns reuse into shared evolution. The maintainers still care for the project, while people beyond the original team can help it improve. Keep this picture: publish, consume, contribute back. We will use the same picture again, but with a much larger artifact.
