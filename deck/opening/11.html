Juan David → the architecture behind the idea.

1:00 · Oscar · Opening 11/11

GitOps is a set of practices that can connect these reviewed decisions to operations. Git holds a declarative, versioned description of desired state. [Step 1] A controller automatically pulls that description. [Step 2] It observes the running system and attempts to reconcile the differences. The illustration now shows that distinction: desired state is the target, while actual state may lag behind it. [Step 3] Reconciliation attempts to move the running system towards the target. A merge changes what we want; successful execution still needs verification. InnerSource describes how people contribute and maintain the shared foundation. GitOps connects that collaboration to the operational loop. [Step 4] We now have the problem, the proposed landing zone, and the boundaries we need to design. Juan David will show how the shared base, company context and GitOps fit together in the technical architecture.
